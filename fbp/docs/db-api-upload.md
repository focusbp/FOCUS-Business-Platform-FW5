# DB APIの分割添付アップロード

## 用途と制限

署名認証済みの管理クライアントから、管理ノートの既存レコードに画像・ファイルを登録する。通常の`add`／`edit`は従来どおりJSONのレコード値を扱い、添付の実体保存は本APIが担当する。対象は`common`の管理ノートの`file`／`image`項目。任意のクラスDB、設定DB、保存パスの指定は受け付けない。公開範囲や配信認証は変更しない。

初期上限は1ファイル256 MiB、断片1 MiB、同時8件、予約容量合計1 GiB。これらはアプリ単位。Base64による送信量はバイナリの約4/3となる。PHP／Webサーバーのリクエスト上限はJSONの付帯情報を含め約1.34 MiB以上必要。ファイル項目は画像以外も登録でき、画像項目は実体がJPEG・PNG・GIFのものに限定する。画像は標準の幅・サムネイル設定を適用し、元データと保存後データのハッシュを区別する。画像寸法とPHPのメモリ制限も検査する。

## 認証と本文の固定

全操作を`db_api`クラスのPOSTとして呼び、既存の`verify_api_request()`で検証する。JSON本文のSHA-256を`body_sha256`クエリーへ入れ、そのクエリーを既存HMAC署名に含める。本文とダイジェストが一致しない要求は拒否する。既存署名の5分の時刻許容は維持し、nonce仕様は変更しない。アップロードIDだけでは操作できず、開始したAPIキーのハッシュと対象アプリに紐付ける。キーを切り替えると旧アップロードの継続操作はできない。

## 操作

| 関数 | 入力 | 動作 |
| --- | --- | --- |
| `upload_begin` | request_id、table、id、field、filename、size、sha256、replace | 対象と上限を確認し、upload_id、chunk_size、chunk_count、expires_atを返す |
| `upload_chunk` | upload_id、index、size、sha256、content_base64 | 0始まりの断片をデコード・照合して保存 |
| `upload_status` | upload_id | 状態と受信済み番号を返す。受信中の実体欠損・破損は未受信へ戻す |
| `upload_commit` | upload_id | 結合・全体照合・実体保存・レコードへの紐付けを行う |
| `upload_abort` | upload_id | 確定前の処理を中止し、一時実体と予約済みファイルを削除 |
| `upload_cleanup` | 空オブジェクト | 期限切れ受信データと完了・中止データの残存実体を回収 |

`request_id`は16～128文字の英数字・ハイフン・アンダースコア。`size`・`id`・`index`はJSON整数、`replace`はJSON真偽値。SHA-256は小文字の16進64文字。ファイル名は255バイト以内で区切り文字・制御文字を禁止する。空ファイルは0バイトの断片1件として扱う。

同じrequest_id・同じ入力の開始要求、同じ番号・同じ内容の断片、確定の再送は同じ結果を返す。同じID・番号で異なる内容を送った場合は409。順不同の断片受信と別プロセスからの同時再送に対応する。`upload_begin`の再送でも入力の一致を検査する。

## 保存・排他・復旧

状態は`receiving → committing → prepared → complete`。中止は`aborted`、受信期限切れは`expired`。FFMの受付DB、ファイルDB、ノート定義DB、対象DBを先に開き、ロック順序の再取得後に状態を読み直す。独自flockは使用しない。対象の更新には通常FFMを使い、DSPを迂回しない。

受信中は対象レコードを変更しない。確定時に開始時の添付IDと現在値を比較し、競合時は409で停止する。既存添付の置換は`replace=true`が必要。旧添付の実体・ファイル情報は自動削除しないため、参照の確認・不要ファイルの整理は別途行う。

実体は管理されたupload保存領域へストリームコピーし、標準ファイルDBにレコード・所有ノートを登録する。保存名はサーバーが発行する識別子から生成し、クライアントは指定できない。画像処理後の容量・ハッシュを記録し、紐付け前に再検査する。複数DBの一括ロールバックや電源断に対する原子性は保証しない。

ファイル情報の採番直後、実体保存後、対象更新後にプロセスが終了しても、受付状態と固定の予約保存名から照合し、確定再送で二重採番・二重紐付けを防ぐ。`committing`／`prepared`は自動失効・削除せず、確定再送または中止で解決する。cleanup応答の`needs_recovery`に期限を超えた未解決IDを返す。

断片と結合用実体は`get_temp_dir()`を基点とするアプリ別・受付別の非公開領域へ置く。受信期限は最終受信から24時間、開始から最大7日。statusの参照では延長しない。期限切れ受信は新規受付時にも回収する。完了・中止・期限切れの受付記録はcleanupで最終更新から7日後に削除するため、再送の保証範囲も受付記録の保持期間内となる。管理保存先でのストリームコピー中に強制終了した場合の`managed-copy-*`も、7日後にcleanupで回収する。cleanupは管理クライアントから明示実行できる。定期実行の新規登録は行わない。

応答はfile_id、元ファイル名、元容量・ハッシュ、保存後容量・ハッシュ、実体MIMEを含み、実体の内部パス・認証情報は返さない。

## 検証

専用検証アプリの`tests/db_api_upload`に、実Controller・FFM・署名HTTPを使う隔離テストを置く。通常登録、画像変換、サムネイル、順不同・同時・重複送信、欠損からの再送、キーの分離、DSP拒否、明示置換、競合、期限・容量、実プロセスの強制終了からの復旧を確認する。80 MiBのファイルをPHPメモリ上限64 MiBで登録し、全体をメモリに載せず保存できることも検査する。
