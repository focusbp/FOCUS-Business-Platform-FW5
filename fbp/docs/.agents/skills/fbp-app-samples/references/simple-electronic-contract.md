# 簡易電子契約（管理画面）

管理者がPDFを1件登録し、作成者と相手が別々にメール認証・承認する再利用サンプル。甲乙の指定・顧客区分・代理店情報への依存はない。Standard Screenの一覧と追加操作ダイアログ、ログイン不要の専用署名画面を組み合わせる。

## 利用者の流れ

1. 管理一覧の「新規追加」→相手の氏名・メールアドレス。
2. PDFを1件添付（20MB以下・破損なし・暗号化なし）。
3. 契約名・双方・PDFを確認し、「双方にメールを送信」で初めて登録。
4. 双方へ異なる専用URLを送る。作成者も管理画面から承認を代行せず、自分のメールで認証する。
5. 各人がPDF確認→4桁コードの送信・照合→同意して承認。
6. 双方の承認後、原本と承認記録を結合した完成PDF、証跡JSON・テキストをZIPへ収録し、双方へ完了メール。

自分側の氏名・メールはログイン中の`user`レコードから取得し、POSTの自己申告を使わない。氏名・メールが未登録／不正なら、管理ユーザー情報の登録を案内する。送信時に双方・原本ハッシュを固定し、通常の編集・削除・複製は提供しない。

途中入力は認証ユーザーに結び付けたセッション内だけで保持し、下書きレコードは作らない。新規開始で前の入力と一時PDFを破棄する。一時PDFは`get_temp_dir()`以下へ置き、登録時に管理ファイルへコピーして一時分を削除。放置した一時PDFは次回添付時に2時間経過分を掃除する。

## 導入

コード配置とテスト定義登録を分ける。既存クラス・同名ノート・選択肢・メールキーがあれば停止し、導入先に合わせて適応する。データやSMTP認証情報は自動登録しない。

```sh
php docs/.agents/skills/fbp-app-samples/scripts/install_simple_electronic_contract.php --code-root=<app-source-root>
# 環境の正規同期を行った後、テスト実行環境を明示
php docs/.agents/skills/fbp-app-samples/scripts/install_simple_electronic_contract.php --configure-test-root=<test-runtime>
```

配置物は`assets/simple-electronic-contract/`、[ノートとメール定義](simple-electronic-contract-db.md)を参照。公開ルートは独立した`sample_esign_public`クラスの限定された入口で、導入先の`public_pages`への追記は不要。実行時にSkillや参照元アプリを読む依存はない。

実メールには導入先のSMTP設定が必要。標準では`testserver()`が真の環境で実送信を拒否する。テスト送信が必要な場合は検証専用の依存注入メール送信関数を使い、アプリにテスト送信用の公開入口を追加しない。宛先・本文・専用URL・確認コードはログへ出さない。

## 権限と期限

- 管理操作・一覧・ZIP取得はログインしたアプリ管理者のみ。`SampleESignGuard`を導入先の管理権限の接続点とする。標準の範囲は管理者間で全件共有。作成者限定や部署別にする場合は一覧の絞込みと行操作の両方へ同じ条件を接続する。
- 公開承認URLは送信確定から10日。契約・当事者・用途を結び付けたHMACを検証する。期限切れの承認は不可。
- コードは4桁・10分・誤入力5回まで、60秒間隔・当事者ごと最大30回。コードと認証セッションを世代で結び付け、別セッションの認証や古いコードを承認に転用しない。
- 公開ZIP取得URLは完成から3日。承認URLの期限とは独立する。期限後も権限のある管理者は管理一覧の詳細からZIPを取得できる。
- 公開側の取得は有効な専用URLを持つ本人に共有する方式。管理ログインの認証とは別。
- 標準の編集・削除・複製・汎用メディア取得はvisibility filterで拒否する。ノートの生データを取り扱える管理API資格情報は信頼された管理者として扱う。

## 更新・失敗時

同じ送信確定の再送は同じ契約を使い、送信済み宛先へ重複通知しない。未送信メールや両者承認後の生成失敗は管理一覧の「詳細」から再試行する。再送間隔は30秒以上、最大20回。期限を過ぎた公開完了通知は再送しない。

FFMで関連DBを先に開き、読取り・重複判定・更新を排他内で行う。双方の同時承認でも完成ファイル・通知は一度だけ作成する。外部メールの配信成功と状態記録の間でプロセスが停止した場合の厳密な一回配信までは保証しない。

## 検証

```sh
php docs/.agents/skills/fbp-app-samples/scripts/test_simple_electronic_contract.php <configured-test-runtime> <temporary-parent-directory>
```

空の実FFMと架空user・模擬メールだけで検証する。実運用データは読まず、必要な形式定義のみ使う。成功・失敗後に専用一時領域を削除する。PHP拡張mbstring/zip、標準PDF生成、`pdfinfo`・`pdfunite`・`timeout`が必要。

検証済み：54項目のuser取得・自己情報偽装無視・権限・途中未登録・メール部分失敗・期限・コード制限・CSRF・同時承認・二重通知防止・証跡HMAC。隔離HTTPでは実ハンドラによる双方の別セッション承認、ZIP取得・内部PDFの内容、管理側取得・一般ユーザー拒否、公開側スマホ幅を確認。実管理画面でも標準一覧から入力→添付→確認、項目エラー、userの自分側表示、スマホ幅を確認。実メールは送信していない。
