# お客様と共有する移行手順

サイト移行の初回提案・着手案内では、対象範囲とともに次の基本形を顧客向けコメントで共有する。すでに共有・合意済みなら全手順や承認を繰り返さず、現在地・次工程・変更点を伝える。FOCUS等の会話上のサービス名を使い、ツール名やサーバー認証の詳細は顧客向け説明に持ち込まない。

## 基本形と許可の扱い

| 工程 | 作業と確認 | お客様との共有 |
|---|---|---|
| 1. 調査・テスト構築 | 取得範囲を確認し、ページ・記事・素材・必要な機能をテスト環境へ再構築する | 維持する範囲、取得できないもの、再現できないものを案内する。開発用URLを閲覧できると約束せず、環境の提供条件に合う確認資料を使う |
| 2. FBP本番への移行 | 許可された範囲でバックアップ後、コードとページ・記事・画像等を本番へ取り込み、件数・内容・参照を照合する | DNS切替前にもFBP本番への配置・取込みが必要なことを伝える。「本番に出さない」等の明示指示が残る場合はこの工程を待つ |
| 3. 本番での目視確認 | 実際に表示できるFBP側の本番URLで画面・画像・リンク・動作を確認し、お客様にも見比べてもらう | 実表示を確認したURLを案内し、未対応部分も併記する。コード配布だけ、管理画面だけ、画像キャプチャーだけで本番表示を確認済みとしない |
| 4. 独自ドメインの事前設定 | 許可の下で、設置先にドメインの受け口・公開トップ・wwwの扱い・証明書取得用の経路等を用意し、DNS変更前の接続先指定で表示先を検査する | FBP本番取込みと事前設定が整う前にDNSの接続先変更を依頼しない。既存設定は再追加せず確認する。この準備は本番確認と並行してよい |
| 5. DNS切替 | 表示内容の確認と切替許可が揃ってから、必要なWeb用レコードと変更先を案内する。メール用設定を保持する | 誰が変更するかを明示し、顧客作業なら変更後の返信を依頼する。手順の説明やFBP本番への配置承認だけでDNS変更まで許可されたと扱わない |
| 6. HTTPS有効化・最終確認 | 顧客作業の場合は完了返信を受け、DNS一致を確認し、必要な証明書発行・HTTPS/www転送・旧URL・画面・素材・機能を確認する | 確認済み範囲と残作業を報告する。noindexの解除時点は合意に従い、維持指示があれば解除しない |

通常の独自ドメイン設定の具体的な操作は環境の専用手順に従う。HTTP認証による証明書発行等、DNS切替後にしか完了できない工程があるため、「独自ドメインの準備」と「HTTPSでの最終確認」を分ける。Web用TTLの事前調整は環境手順で案内できるが、DNS接続先の切替とは区別する。

**「FBP側の本番へ配置すること」と「既存ドメインの行先を切り替えること」は別工程。** FBP側の本番URLはDNS切替前でも閲覧可能になる場合がある。noindexは検索登録を抑制する設定であり、閲覧を制限する認証ではない。公開範囲・閲覧制限に明示要件があればそれに従う。

工程の説明は新たな許可を発生させない。開発、本番配置・データ取込み、ドメインのサーバー設定、DNS切替、検索登録について、人間の履歴から現在有効な許可・禁止を引き継ぐ。実施前の工程に必要な許可だけが不足している場合は、その内容と影響を具体的に尋ねる。すべての工程に毎回別承認を要求したり、合意済みの方針を再質問したりしない。自動処理へ渡す場合も実行指示と進捗記録へ残す。

## 初回コメントの例

> 移行は、次の順で進めます。
>
> 1. 元サイトのページ・ブログ記事・画像などを確認し、FOCUS上に再構築します。取り込めないものや再現できない部分は一覧でお知らせします。
> 2. 本番への配置をご承認いただいた範囲で、FOCUS側の本番環境へページ・記事・画像を入れます。この時点では、現在のドメインの行先は変えません。
> 3. FOCUS側の本番URLをご案内し、元サイトと見比べていただきます。DNSを切り替える前に、この確認とFOCUS側の独自ドメインの事前設定を済ませます。
> 4. 表示内容の確認と切替の了承が揃ったら、DNSの変更内容をご案内します。お客様に設定いただく場合は、変更後に完了のご返信をお願いします。
> 5. 切替後、HTTPS・ドメインの転送・ページや画像の表示などを最終確認して結果をご報告します。
>
> 検索エンジンへの登録設定と公開時期は、ご指定に沿って進めます。

これは構成例。実際の依頼・共有済み工程・公開許可・noindex指示に合わせて短く調整し、未確認の閲覧URLや取得件数は埋めない。「公開してください」がどの工程を指すかは履歴を読んで判断し、必要な場合だけ確認する。
